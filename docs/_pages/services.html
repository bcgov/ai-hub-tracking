Available AI Services

This page describes the services that the platform makes available to tenant teams, what a tenant actually receives when it is onboarded, and how access is controlled. It is intended to answer the practical question, “What can my team use here?”

All services run behind private endpoints, not on the public internet. Tenant access goes through the platform gateway by using the team's subscription key. See the internal gateway endpoints reference for the gateway-specific details.

Model Providers

Each tenant accesses model deployments through its dedicated AI Foundry Project endpoint, routed via APIM. OpenAI is the baseline model family for tenants across environments. Additional provider families such as Cohere and Mistral are enabled only when they are explicitly deployed for a tenant.

Embedding Models

Embedding models convert text into dense vector representations — essential for search, RAG (Retrieval Augmented Generation), and semantic similarity tasks.

Model Dimensions Best For Quota (Canada East) Lifecycle

text-embedding-ada-002 1,536 Legacy compatibility 10,000 TPM GA retires 2028-02-09
💡
TPM = Tokens Per Minute. OpenAI quotas shown above are subscription-wide limits; each tenant is allocated a share. Allocation is typically 1% per tenant in each environment, but provider-specific deployments can use different quotas. See model-deployments.md for the current allocation source of truth.
💡
Provisioned throughput uses input-equivalent TPM, not a simple raw input + output token total. For GPT-5.1, APIM now enforces non-streaming requests on a dedicated PTU backend using actual response usage with prompt tokens weighted x1 and completion tokens weighted x8. The lower raw-token cap is retained only as a fallback for streaming requests, where APIM cannot reliably read final SSE usage before returning the stream.

Cognitive Services

Beyond the model providers listed above, each tenant can access the following Azure AI capabilities through the hub.

Platform rule: Azure AI Language is reserved for PII detection in this hub. If a tenant needs summarization, sentiment, classification, question answering, or orchestration behavior, implement that workload on tenant Azure AI Foundry model deployments instead of the shared Language service.

Document Intelligence

Extract structured data from unstructured documents — forms, invoices, PDFs, scanned images. Supports custom models trained on your document types.

Dedicated instance per tenant — View setup guide →

Content Understanding

Analyze documents with Azure Content Understanding analyzers, such as prebuilt-layout, and get the content back as Markdown. Runs on its own Microsoft Foundry resource in Canada Central.

Dedicated instance per tenant, opt-in — See how to use it ↓

Azure AI Language / PII Detection

Detect and redact Personally Identifiable Information (PII) from text using Microsoft's pre-trained PII models. In this platform, the shared Language integration is scoped to PII detection only.

Shared hub service — View PII guide →

Speech Services

Convert speech to text and text to speech. Supports real-time transcription, batch audio processing, and custom voice models. Optimized for Canadian English and French.

Dedicated instance per tenant — See FAQ for details

AI Search

Managed vector + full-text search service for building RAG pipelines, semantic search over documents, and hybrid retrieval. Integrates directly with AI Foundry for grounding model responses.

Dedicated instance per tenant

Using Content Understanding

Azure Content Understanding is available to tenants that opt in, through the generally available API version 2025-11-01. It does not run on the shared AI Foundry Hub. Each enabled tenant gets its own Microsoft Foundry resource, with its own model deployments, in the tenant resource group.

The reason is region. The shared hub runs in Canada East. Microsoft's Content Understanding region list (page updated 2026-10-19, checked 2026-11-16) includes Canada Central but not Canada East, so these resources are deployed in Canada Central.

Item Details
How to enable Set content_understanding = { enabled = true } in params/<env>/tenants/<tenant>/tenant.tfvars. Every tenant file must contain this block, set to true or false, because the tenants variable is map(any). Region, models, and capacity come from shared_config.content_understanding in params/<env>/shared.tfvars.
Enabled today ai-hub-admin dev only. Disabled for every other tenant in dev, test, and prod.
Resource Microsoft Foundry resource (kind AIServices) named <tenant>-cu-<4-character suffix>, in the tenant resource group, in Canada Central, with a system-assigned managed identity.
Network Public network access is disabled. The resource has a private endpoint, pep-<name>, in the tenant's private endpoint subnet. The Landing Zone policy manages its DNS record.
Authentication Call the gateway with your tenant's APIM subscription key in the api-key header, the same key you use for other services. The gateway removes that header and calls the resource with its own managed identity, which has the Cognitive Services User role on the resource. Key (local) authentication is disabled on the resource.
Rate limits Content Understanding requests count toward the tenant's existing per-minute request limit for non-OpenAI services.

Calling Content Understanding

The base URL is https://<gateway>/<tenant>. The tenant-info endpoint returns it as services.content_understanding.endpoint.

Method Path (add ?api-version=2025-11-01) Purpose
POST /contentunderstanding/analyzers/{analyzerId}:analyze Analyze a file given by URL, {"inputs":[{"url":"..."}]}, or as base64, {"inputs":[{"data":"<base64>","mimeType":"application/pdf"}]}. Returns 202 with an Operation-Location header.
POST /contentunderstanding/analyzers/{analyzerId}:analyzeBinary Analyze a file sent as the raw request body. Returns 202 with an Operation-Location header.
GET /contentunderstanding/analyzerResults/{resultId} Get the result. status is NotStarted, Running, Succeeded, Failed, or Canceled. The extracted Markdown is in result.contents[].markdown.
GET / PATCH /contentunderstanding/defaults Read or set the model defaults. See the one-time setup below. 
# Analyze a document by URL with the prebuilt-layout analyzer
curl -i -X POST "https://<gateway>/<tenant>/contentunderstanding/analyzers/prebuilt-layout:analyze?api-version=2025-11-01" \
  -H "api-key: <your-subscription-key>" \
  -H "Content-Type: application/json" \
  -d '{"inputs":[{"url":"https://example.com/document.pdf"}]}'

# 202 Accepted. Poll the Operation-Location URL until status is Succeeded.
curl -s "<Operation-Location value>" -H "api-key: <your-subscription-key>"

The gateway rewrites the Operation-Location header so that it points at the gateway host instead of the resource, as it does for Document Intelligence. Polling therefore goes through the gateway with the same subscription key.

One-time setup per tenant: model defaults. Content Understanding has to be told which deployments to use. A single PATCH per tenant maps the model names and the prebuilt-analyzer aliases to the tenant's deployments. Terraform cannot set this: it is a data-plane setting, the resource has no public network access, and deployments run on GitHub-hosted runners. Apply it through the gateway instead. prebuilt-layout, prebuilt-read, and prebuilt-digitalParse do not need a language or embedding model (Prebuilt analyzers). 
curl -X PATCH "https://<gateway>/<tenant>/contentunderstanding/defaults?api-version=2025-11-01" \
  -H "api-key: <your-subscription-key>" \
  -H "Content-Type: application/merge-patch+json" \
  -d '{
    "modelDeployments": {
      "gpt-5.4": "gpt-5.4",
      "gpt-5.4-mini": "gpt-5.4-mini",
      "text-embedding-3-large": "text-embedding-3-large",
      "prebuilt-analyzer-completion": "gpt-5.4",
      "prebuilt-analyzer-completion-mini": "gpt-5.4-mini",
      "prebuilt-analyzer-embedding": "text-embedding-3-large"
    }
  }'

The same map is in the tenant-info response as services.content_understanding.model_deployments, and a GET on /contentunderstanding/defaults shows what is currently set. See Models and deployments for how defaults work.

Data residency: data at rest stays in Canada Central. GlobalStandard is the only deployment type for these models in Canada Central, so inference may be processed outside Canada. This is the same posture as the existing model deployments on the shared hub.

What Each Tenant Gets

The hub operates on a shared platform, dedicated data model. Expensive control-plane infrastructure is shared; all data-plane services are isolated per tenant.

Shared Platform Infrastructure

Provisioned once, used by all tenants. Cost is split proportionally.

  • AI Foundry Hub — shared model registry & endpoint
  • API Management (APIM) — unified API gateway
  • Application Gateway + WAF — TLS termination, routing
  • Virtual Network & Private DNS — private connectivity
  • Azure Container Registry — shared container images
  • Log Analytics Workspace — centralized monitoring

Dedicated Per-Tenant Resources

Provisioned exclusively for your team. Cost is directly attributed to you.

  • AI Foundry Project — your own API endpoint & prompt flows
  • Model Deployments — OpenAI baseline plus any tenant-specific Cohere or Mistral deployments assigned to your project
  • Document Intelligence — your own instance & models
  • Content Understanding — your own Microsoft Foundry resource and model deployments in Canada Central (when enabled)
  • AI Search — your own indexes for RAG
  • Speech Services — your own instance
  • Key Vault — your secrets, isolated from other tenants
  • Storage Account — your documents & data
  • Cosmos DB — your NoSQL database (when enabled)
  • Resource Group — rg-{tenant}-{env}
  • APIM Subscription Key — your API credential
Cross-tenant isolation is enforced at the network and identity layer. Dedicated Key Vaults and Resource Groups mean one tenant cannot access another tenant's data — even if they share APIM or AI Foundry Hub infrastructure. See ADR-010: Multi-Tenant Isolation Model for the full security rationale.

Accessing Your API Credentials

Approved tenant administrators can view and copy their APIM subscription keys for each environment directly from the portal — no platform team involvement required.

Credentials Panel

Navigate to your tenant's detail page in the Tenant Onboarding Portal. If your account is listed as a tenant admin and the tenant is approved, a Credentials panel appears below the configuration summary.

What You Can See

  • Three environment tabs (dev / test / prod) — credentials load on demand when you select a tab.
  • Primary and Secondary subscription keys — values are always masked. Use the copy button to place a key on your clipboard.
  • Rotation metadata (when rotation is enabled) — shows last rotation date, next scheduled rotation, and which slot is currently safe to use.
  • Tenant info panel (expandable) — lists your base APIM URL, enabled services, and deployed model names and capacities.

Security Notes

  • Key values are never displayed as text in the page. Only copy-to-clipboard is supported.
  • Access is restricted to users listed in your tenant's admin_users configuration.
  • Each environment's credentials are fetched independently from the hub Key Vault using the portal's Managed Identity.
